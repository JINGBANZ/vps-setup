Connection details ↗
The coordination service shares device information and permissions. It does not carry your terminal or desktop session. A relay forwards encrypted packets and cannot read their contents. Architecture · Encryption

What makes direct possible?

Both devices are online and authorized, with a usable UDP path through their routers and firewalls. They can be on different Wi-Fi networks, in different countries. Same-network access is often simpler. How NAT traversal works ↗

What if it stays relayed?

Restrictive firewalls or difficult NAT can prevent a direct path. Tailscale keeps checking. Your apps still use the same address; relay throughput and latency may be less favorable.

Check the actual route after connecting with tailscale ping mac-mini or tailscale status. Your Hetzner VPS may join as another peer; this design does not require routing through it.

Desktop: built into macOS

On the mini: System Settings → General → Sharing → Screen Sharing. Allow your local user. On the laptop, open Screen Sharing and enter the mini’s Tailscale IP or MagicDNS name.

Sign in with the mini’s local macOS username and password. Different Apple IDs are fine. The script offers guidance; Screen Sharing itself needs no package installation. Apple ↗

Terminal: Mosh + SSH + tmux

Enable macOS Remote Login and authorize your user. Mosh uses SSH for initial authentication, then UDP for the terminal. Allow the needed services through your Tailscale policy and host firewall.

Install Mosh on both computers. Run tmux on the mini. Mosh ↗

mosh youruser@mac-mini

Startup is part of the design

For unattended use, the proposed mini configuration uses the CLI tailscaled system service, which supports running before a desktop login. Existing GUI installations require a deliberate startup choice, not a second competing installation. Tailscale variants ↗

Remote reachability after a reboot also depends on disk unlock and networking. We should verify a planned reboot before relying on unattended recovery; the setup should preserve FileVault settings.

03

Disconnecting is different from rebooting

tmux owns the terminal session on the mini. Your laptop attaches to it.

Session lifecycle
Agent running on the miniYour laptop is attached to tmux. Commands execute on the mini.

The optional t shortcut

On the miniWhat happens
t jarvisCreate or rejoin the “jarvis” session.
t tradingCreate or rejoin a separate session.
tCreate or rejoin the default “main” session.
Ctrl+B, then DDetach; leave programs running.

Launch your agent inside the session. Naming a session does not automatically open a matching repository or start an agent. tmux documentation ↗

After the mini restarts

tmux and its running processes stop. Start a new session and restart the agent; recovery depends on the agent’s saved history.

Restoring window layouts is different from preserving a running task.

Proposed actions

    A real installer would ask you to confirm this plan before making changes. This preview only illustrates the design.

    Reuse existing tools

    Inspect executable paths, versions, install methods, service state, and authentication status where safely available. Existing working tools are reused; upgrades are a separate choice.

    Own small config blocks

    Back up changes, replace only managed shell blocks, and avoid duplicate shortcuts. Preserve existing credentials, projects, and running sessions. Deselecting means skip.

    Verify reruns

    Check a second identical run, an interrupted run, and a run selecting one new component. Detect conflicting Tailscale variants before changing the network setup.

    Mac scope: PostgreSQL, GitHub Actions runner, and disk-usage monitoring are excluded. Node.js and Bun are independent, optional project runtimes. Homebrew is a dependency for selected packages, installed only when needed. Homebrew documentation ↗
